# Replication package for "Fast Solution of Dynamic Intra-Household Bargaining Models"

Adam Hallengreen, Thomas H. Jørgensen and Annasofie M. Olesen

Submitted to *Quantitative Economics*. The code is also available at <https://github.com/ThomasHJorgensen/FastBargaining>.

## Overview

The code in this package solves, simulates and calibrates the dynamic household models in the paper. It is written in Python, and the solution and simulation of the application model run in C++ that Python compiles with Microsoft Visual C++. No microdata are used. The application model is calibrated to 13 published statistics, which are typed directly into the code (see the data availability statements below).

A single master notebook, `run_all.ipynb`, runs six notebooks in sequence. Together they generate all figures and tables in the paper and the Supplemental Material that come from computations: Figures 1–4, Tables 2–4 and 6–8, and Figure S1. Tables 1, 5 and S1 list parameter values that are inputs to the code, and Figure S2 is a stylized drawing made directly in LaTeX.

The full run took about 33 hours on a 104-core server with 1.5 TB of RAM. Three of the notebooks need between 1.2 and 2 TB of memory (RAM plus page file), so the package cannot be run on a desktop computer. See [Computational requirements](#computational-requirements).

**Eckstein, Keane and Lifshitz (2019).** We use the "Data" column for the 1975 birth cohort in Tables J-I (wages and employment) and J-II (marriage rate) of the article's Supplemental Material. Wages are real annual wages of full-time, full-year workers in thousands of 2012 USD. Employment is the share of the population working at least 10 hours per week. The 1975 cohort is observed only until age 41, so the "ages 35–44" cell covers ages 35–41. The article and its Supplemental Material are on the Econometrica website (<https://doi.org/10.3982/ECTA14474>). Access is free.

**Blundell, Pistaferri and Saporta-Eksten (2018).** The target is the sample mean of total household consumption in Table 1, panel B: 42,716 USD in 2010 prices, excluding durables. The sample is married couples in the Panel Study of Income Dynamics (PSID) in which both spouses work. The article is in the *Journal of Political Economy* (<https://doi.org/10.1086/698752>), which requires a subscription or institutional access. An earlier version is freely available as NBER Working Paper 24006.

**Meyer and Sullivan (2023).** The target is the 2017 level of the 90/10 ratio of well-measured consumption. It is computed from Table 2 as the 1960–61 level (3.33) times one plus the 1961–2017 change (9.54 percent). Consumption is measured from the Consumer Expenditure Survey at the family level, equivalized with the NAS scale, and weighted by persons. The article is in the *Journal of Political Economy* (<https://doi.org/10.1086/721702>), which requires a subscription or institutional access. An earlier version is freely available as NBER Working Paper 23655.

**American Time Use Survey (ATUS).** The targets are average hours per day in primary activities for women and men aged 35–44 in 2024. They average over all persons in the age group and all days of the week. They are taken from Table 3, "Time spent in primary activities for the civilian population by age, sex, race, Hispanic or Latino ethnicity, marital status, and educational attainment, 2024 annual averages", of the BLS news release "American Time Use Survey – 2024 Results" (USDL-25-1060, June 26, 2025): <https://www.bls.gov/news.release/archives/atus_06262025.pdf>. The values are in the rows "35 to 44 years" under "Men, 15 years and over" and "Women, 15 years and over" (page 11). Market work is "Working and work-related activities". Home production is the sum of "Household activities", "Purchasing goods and services", "Caring for and helping household members" and "Caring for and helping nonhousehold members". The code converts hours per day to hours per week (× 365/52). The paper reports annual hours (× 365). The data are public domain and free to access without registration. The values were checked against the release on October 27, 2026.

**Tax schedules.** The model taxes gross labor income with the 2000 U.S. federal income tax brackets and marginal rates for singles and married couples (Supplemental Material, Section S3 and Table S1). These are as tabulated in Bronson, Haanwinckel, and Mazzocco (2024, Table A.1). They are hard-coded in the C++ files listed above.

**Externally calibrated parameters.** The parameters in paper Table 5 come from the studies cited there, not from data. They are set in `Application/DynamicTimeAllocationModel.py` (see the list of tables below).

## Computational requirements

### Software Requirements

- [x] The replication package contains one or more programs to install all dependencies and set up the necessary directory structure.

The Python dependencies are installed from `pyproject.toml` with `uv.lock` and `.python-version`, from `requirements.txt` or from `environment.yml` (see the instructions to replicators). The output folders are part of the package.

- **Operating system: Windows (64-bit).** The code was last run on Windows Server 2022 Datacenter (version 10.0.20348). Windows is required because EconModel compiles the C++ code by writing and running a Windows batch file that calls the Microsoft Visual C++ compiler, and it loads the result as a `.dll`.
- **Microsoft Visual Studio Community 2022** (version 17.7.6, MSVC 14.37.32822) with the workload "Desktop development with C++". EconModel looks for `vcvarsall.bat` in `C:/Program Files/Microsoft Visual Studio/2022/Community/VC/Auxiliary/Build/` and in the corresponding folders of Visual Studio 2019 Community and Visual Studio 18 Community. Install the Community edition in its default location. Other editions are not found automatically.
- **NLopt 2.4.2**, 64-bit Windows DLL (Johnson 2014). It is included in `Application/cppfuncs/nlopt-2.4.2-dll64/`, together with the import library `libnlopt-0.lib`, which was generated with `lib /def:libnlopt-0.def /machine:x64`. The original archive is included as `Application/cppfuncs/nlopt-2.4.2-dll64.zip`.
- **Python 3.13.13** (CPython build distributed by uv), managed with **uv 0.11.8**. All Python packages are pinned in `uv.lock` (and in `requirements.txt` for pip). The main packages are:
  - EconModel 0.17, installed from GitHub at commit `367f22048e49cad10cc54c3f09f5f313180cca6f` (<https://github.com/NumEconCopenhagen/EconModel>), so `git` must be installed
  - consav 0.12
  - numpy 2.4.4, numba 0.65.1, scipy 1.17.1, pandas 3.0.2
  - matplotlib 3.10.9, seaborn 0.13.2
  - papermill 2.7.0, ipykernel 7.2.0 (to execute the notebooks)

**Compilation.** The C++ code is compiled automatically by `Application/01. Calibration.ipynb` (`do_compile = True`) through EconModel. The resulting compiler call, run from `Application/` after `call vcvarsall.bat x64`, is

```bat
cl /LD /EHsc /O2 /openmp cppfuncs/solve.cpp setup_omp.cpp cppfuncs/nlopt-2.4.2-dll64/libnlopt-0.lib
```

It produces `Application/solve.dll`. `setup_omp.cpp` is a small file that EconModel writes and deletes on the fly. The files `par_struct.cpp`, `sol_struct.cpp` and `sim_struct.cpp` in `Application/cppfuncs/` are written automatically by EconModel from the Python model, and `solve.cpp` includes the remaining C++ files. A compiled `Application/solve.dll` is included, so notebooks 02–04 can also run without a compiler.

### Controlled Randomness

- [x] Random seed is set at line 73 of program `Illustration/UnitaryModel.py` and at line 150 of program `Application/DynamicTimeAllocationModel.py`
- [ ] No Pseudo random generator is used in the analysis described here.

All random numbers are drawn in Python with NumPy's global generator before the C++ code is called. The C++ code itself draws no random numbers, and its parallel loops write to separate array elements, so the number of OpenMP threads should only affect the run time.

- Illustrative model: `Illustration/UnitaryModel.py`, line 73 (`par.seed = 9210`), used at line 147 (`np.random.seed(par.seed)`). In `Illustration/01. UnitaryHousehold.ipynb` (section "Accuracy measures"), Monte Carlo run `i_mc` sets `par.seed = i_mc`.
- Application model: `Application/DynamicTimeAllocationModel.py`, line 150 (`par.seed = 9210`), used at line 647 (`np.random.seed(par.seed)`). Shocks are redrawn from this seed for every evaluation of the calibration objective. In `Application/03. Timings.ipynb`, Monte Carlo run `i_mc` sets `par.seed = i_mc`.

## Description of programs/code

- `run_all.ipynb`: the master notebook. It runs the six notebooks below in order with papermill. Each notebook is run in its own folder. An executed notebook replaces the original only if it completes without error.
- `Illustration/`: the illustrative two-person unitary model in Section 2 of the paper.
  - `UnitaryModel.py`: model class with VFI, analytical EGM, numerical EGM and iEGM solvers, simulation and accuracy measures.
  - `InterpolationFunctions.py`: helper functions for numerical inversion and interpolation.
  - `01. UnitaryHousehold.ipynb`: generates Figure 1 and Tables 2–3.
- `Application/`: the quantitative household model in Section 4 of the paper.
  - `DynamicTimeAllocationModel.py`: model class (`HouseholdModelClass`). It sets parameters and grids, allocates memory, draws shocks, calls the C++ solver and simulator, and computes moments, the calibration objective and the accuracy measures.
  - `cppfuncs/`: C++ code. `solve.cpp` holds the entry points (`solve`, `simulate`, `accuracy_measures`). `precompute.cpp` holds the intra-temporal precomputation and the iEGM interpolator, `single.cpp` and `couple.cpp` the problems of singles and couples (including the tax functions), and `bargaining.cpp` the limited commitment bargaining protocol. `simulate.cpp` simulates the model, and `index.cpp`, `tools.cpp`, `utils.cpp` and `logs.cpp` are helpers. `nlopt-2.4.2-dll64/` contains NLopt.
  - `01. Calibration.ipynb`: calibrates the model, writes Tables 6 and 7, compiles the C++ code and saves `par_files/calibrated_par.pkl`.
  - `02. Comparisons.ipynb`: plots policy functions and simulations from iEGM, numerical EGM and VFI side by side. These are diagnostic figures that stay inside the notebook. No output from this notebook appears in the paper.
  - `03. Timings.ipynb`: solves the dense "true" model and computes timing and accuracy (Table 4 and footnote 25).
  - `04. Counterfactuals.ipynb`: shows the iEGM interpolator (Figure 2) and runs the productivity-shock simulations (Figures 3–4 and Table 8).
  - `figure_manager.py`, `plots.py`: plotting helpers.
  - `calibrate/`: Sobol and Halton draws for an optional global search (`HouseholdModelClass.global_search`), which `run_all.ipynb` does not use.
  - `par_files/calibrated_par.pkl`: calibrated parameters, see the dataset list.
- `Appendix/`: `Illustrate bargaining algo.ipynb` generates Figure S1 of the Supplemental Material. `figure_manager.py` is the same plotting helper as in `Application/`, with larger fonts.
- `pyproject.toml`, `uv.lock`, `.python-version`, `requirements.txt`, `environment.yml`: Python environment.
- `DEVELOPMENT.md`: how to set up the Python environment with uv, pip or conda, and how to update the dependency files. It is not needed for the replication.

## Instructions to Replicators

All paths are relative to the root of the package. Commands are for the Windows command prompt.

1. Install Visual Studio Community 2022 with the workload "Desktop development with C++" in its default location.
2. Install `git` and `uv` (<https://docs.astral.sh/uv/getting-started/installation/>). `uv` is not needed if pip or conda is used instead (see step 3).
3. Open a command prompt in the root of the package and set up the Python environment with uv:

   ```bat
   uv python install 3.13.13
   uv sync --frozen --python 3.13.13
   ```

   This creates `.venv` with the exact package versions in `uv.lock`.

   Alternatively, use pip or conda. Both install the same package versions from `requirements.txt`, which is exported from `uv.lock`:

   - pip: install Python 3.13.13 from <https://www.python.org/downloads/> and run

     ```bat
     py -3.13 -m venv .venv
     .venv\Scripts\python -m pip install -r requirements.txt
     ```

   - conda: run

     ```bat
     conda env create -f environment.yml
     conda activate fastbargaining
     ```

     This installs Python 3.13 from conda-forge and then the packages in `requirements.txt` with pip.

   `DEVELOPMENT.md` describes the three options in more detail.
4. Optional: if the machine has fewer than 64 hardware threads, set `threads` in the first code cell of `Application/01. Calibration.ipynb`. Notebooks 02–04 take the number of threads from `calibrated_par.pkl`, which notebook 01 writes.
5. Run the master notebook from the root of the package:

   ```bat
   .venv\Scripts\python -m papermill run_all.ipynb run_all.ipynb
   ```

   With conda, run `python -m papermill run_all.ipynb run_all.ipynb` in the activated `fastbargaining` environment instead. Alternatively, open `run_all.ipynb` in VS Code or JupyterLab, choose the `.venv` kernel (or the `fastbargaining` environment with conda) and run all cells.
6. `run_all.ipynb` prints the run time of each notebook. If a notebook fails, it prints `failed` followed by the error, and the original notebook is left unchanged. The outputs are written to `Illustration/output/`, `Application/output/` and `Appendix/output/`. The executed notebooks also contain all printed results.

### Details

- Notebooks 02–04 can be run on their own (from their folder) with the included `calibrated_par.pkl` and `solve.dll`. If `01. Calibration` is run, it overwrites both files, and notebooks 02–04 must be run afterwards.
- The Nelder–Mead search in `01. Calibration` is capped at 500 evaluations of the objective function. The warning "Maximum number of function evaluations has been exceeded" is expected.
- The timing columns of Tables 2–4 depend on the hardware and on other load on the machine. All other numbers are deterministic given the software versions above.
- If the C++ code fails to link to NLopt, delete the folder `Application/cppfuncs/nlopt-2.4.2-dll64/` and set `do_reinstall_nlopt = True` in the first code cell of `01. Calibration.ipynb`. This unpacks the included archive `nlopt-2.4.2-dll64.zip` and regenerates `libnlopt-0.lib`.
